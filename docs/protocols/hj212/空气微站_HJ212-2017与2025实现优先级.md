# 空气微站 HJ 212-2017 与 HJ 212-2025 实现优先级

## 1. 文档目的

本文档用于指导以 ESP32-S3 为主 MCU 的空气微站实现 HJ 212 数据上传。

实现范围限定为环境空气微站，系统编码为 `ST=22`。不以实现污染源数采仪的全部命令集为目标。

当本文档与目标环保平台的正式接入文档不一致时，以目标平台要求为准。

## 2. 当前程序已有能力

当前程序已经具备以下基础，不需要重新设计：

- HJ 212 报文包头、长度、数据段、CRC 和包尾的基础组包。
- `2011` 实时数据上传。
- `2051` 分钟数据上传。
- `2061` 小时数据上传。
- `2031` 日数据上传。
- 失败重试、待发报文落盘和网络恢复后补传。
- 通过配置选择 2017 或 2025 打包分支。

当前主要问题不是“没有上传功能”，而是数据单位、因子编码、统计、Flag、应答校验和 2025 安全机制尚未正确实现。

## 3. 优先级定义

| 优先级 | 含义 | 发布要求 |
|---|---|---|
| P0 | 数据正确性和基本协议正确性 | 不完成不建议接入正式平台 |
| P1 | 可靠性和常见平台兼容能力 | 建议随第一个正式版本完成 |
| P2 | 按平台要求开启的扩展功能 | 确认平台需要后再实现 |
| P3 | 不适用于当前空气微站 | 本产品暂不实现 |

## 4. P0：先把 HJ 212-2017 做正确

### 4.1 系统编码和版本 Flag

- 空气质量微站使用 `ST=22`。
- 2017 版本、不分包、需要数据应答时使用 `Flag=5`。
- 2017 版本、不分包、不需要数据应答时使用 `Flag=4`。
- 不建议在 JSON 中直接保存 Flag 数字。应当根据“协议版本、是否分包、是否应答”自动计算，避免 2017 误用 `Flag=9`。

### 4.2 因子编码

当前空气微站建议使用：

| 因子 | 上传编码 |
|---|---|
| O₃ | `a05024` |
| NO₂ | `a21004` |
| CO | `a21005` |
| SO₂ | `a21026` |

O₃ 不能继续使用 `w34011`，因为 `w` 前缀表示水监测参数。程序中的传感器注册、默认模型、显示、报警和 HJ 212 上传应统一使用 `a05024`。

### 4.3 单位换算和修约

HJ 212 报文中不携带每个数值的单位，接收平台会根据因子编码解释数值，因此不能把 ppb/ppm 原始数字直接写入报文。

平台没有特殊规定时，建议微站内部采用以下口径：

| 因子 | 传感器常见原始单位 | 建议上传单位 | 实时/分钟建议精度 |
|---|---|---|---|
| O₃ | ppb | µg/m³ | 1 位小数 |
| NO₂ | ppb | µg/m³ | 1 位小数 |
| SO₂ | ppb | µg/m³ | 1 位小数 |
| CO | ppm | mg/m³ | 3 位小数 |

程序处理顺序应为：

1. 读取传感器原始值。
2. 转换成平台要求的质量浓度。
3. 使用未提前修约的内部值进行分钟、小时和日统计。
4. 在生成报文时按因子精度修约。

不应把所有因子统一固定为两位小数。

### 4.4 实时、分钟、小时和日统计

- `2011`：上传当前采集值和数据标记。
- `2051`：使用分钟或平台指定时间窗内的全部有效采样。
- `2061`：使用该小时内全部有效分钟数据，不应只取每 3 分钟的数据。
- `2031`：使用当日全部有效小时数据，并记录有效数据覆盖情况。
- 统计前先判断数据有效性，不能把通信失败、缺测或故障当作测量零值。
- 分钟窗口应使用可配置的 `MinInterval`，不要固定为 10 分钟。
- 浓度、温湿度、风速等瞬时/平均量不上传 `Cou`。只有真正的累计量才生成 `Cou`。

### 4.5 数据标记

2017 版空气微站至少应在数据模型中支持：

| Flag | 含义 | 微站判定来源 |
|---|---|---|
| `N` | 正常 | 传感器和通信均正常 |
| `D` | 设备故障 | 传感器故障或无法正常测量 |
| `C` | 校准 | 正在零点/量程校准 |
| `M` | 维护 | 计划维护期间 |
| `T` | 超量程 | 测量值超出当前工作量程 |
| `B` | 通信异常 | 主 MCU 与传感器通信失败 |

不能仅使用一个 `is_valid` 布尔值将所有异常都简化为 `D`。

### 4.6 数据应答校验

上传报文要求应答时，收到 `9014` 不能只做字符串包含判断。至少需要校验：

- `##` 包头和 `CRLF` 包尾。
- 数据段长度。
- CRC16。
- `CN=9014`。
- QN 与当前待确认报文一致。
- MN 与本设备一致。

建议使用小型增量式帧解析器，不在 RAM 中长时间保存大字符串。

## 5. P1：2017 可靠性与平台兼容

### 5.1 长度限制和分包

- 生成数据段后必须检查长度，单包数据段不超过 1024 个字符。
- 超出限制时使用 `PNUM` 和 `PNO` 分包，并设置对应的 Flag 分包位。
- 空气微站因子数量少时很少触发，因此可以放在 P1，但不能没有越界保护。

### 5.2 QN 唯一性

- QN 使用 `YYYYMMDDhhmmsszzz`。
- 使用真实毫秒或同秒递增序号，不能永远固定为 `001`。
- 重发同一报文时保留原 QN；生成新业务报文时使用新 QN。

### 5.3 上传间隔和超时重试配置

至少让以下配置真正生效并持久化到 NVS：

- `RtdInterval`：实时数据上传间隔。
- `MinInterval`：分钟数据窗口及上传间隔。
- `OverTime`：应答超时。
- `ReCount`：重发次数。

发送任务不应再使用固定 5 秒超时、固定 3 次重试或每个数据包固定阻塞 15 秒。

### 5.4 时间校准

建议实现：

- `1011`：提取/上传现场机时间。
- `1012`：设置现场机时间。

空气微站的分钟、小时和日数据依赖正确的整分、整点边界，因此时钟正确性比远程仪器控制更重要。

## 6. P0-2025：在正确的 2017 内核上升级

2025 不再单独复制一套上传代码。建议共用因子处理、统计、CP 生成、CRC、应答和补传逻辑，仅在协议层保留版本差异。

### 6.1 2025 Flag

- 2025 版本、不分包、需要数据应答时使用 `Flag=9`。
- 2025 版本、不分包、不需要数据应答时使用 `Flag=8`。
- 分包时再由统一的 Flag 计算函数设置分包位。

### 6.2 2025 数据标记

空气微站在 2025 中主要使用：

- `N`：正常。
- `D`：设备故障，包括传感器、供电或内部通信故障。
- `C`：校准。
- `M`：日常维护。
- `T`：超量程。

不需要实现固定污染源的 `Td`、启动、停炉、闷炉等生产工况标记。

报文不能将所有数据硬编码为 `Flag=N`。

### 6.3 SM4 加密和密钥管理

当 DTU/4G 通过公网上传，或目标平台要求完整的 HJ 212-2025 安全机制时，此项为 P0。

需要实现：

- SM4，128 位密钥、ECB 模式、Nopadding。
- 按 2025 要求对指定数据范围加密，再组装最终报文和校验。
- 每台设备独立的初始密钥。
- `1014` 获取和下发新密钥。
- `SKCreateTime` 和最长 90 日有效期管理。
- 新密钥启用后，历史补传数据使用新密钥。
- 密钥只保存在受控的 NVS 区域，不通过日志、串口、JSON 或明文文件输出。

为减少 ESP32 资源占用，SM4 应作为独立的可选协议模块，采用单块/小缓冲区处理，不在内存中同时保留多份完整报文。

### 6.4 2025 补传标志

- 首次正常上传不带 RF。
- 从本地待发队列恢复上传时增加 `RF=1`。
- 不能将原始未带 RF 的完整字符串原样重发。
- 补传时优先保障新数据上传，避免历史数据堵塞实时队列。

## 7. P1-2025：设备身份和心跳

### 7.1 设备身份

在目标平台支持 2025 注册流程时实现：

- `1001`：上传数采仪/微站硬件序号。
- `1002`：接收平台分配的 MN。
- CPUID、MAC 等硬件指纹。
- `3019`：上传自动监测设备唯一标识。
- MN 和设备标识持久化，上电后不得随机变化。

如果当前地方平台仍由人工分配 MN，可以先保留现有配置方式，将注册流程作为编译或配置开关。

### 7.2 `9015` 心跳

- 实现一个低频心跳定时器。
- 只在长连接空闲且目标平台要求时发送。
- 正常数据正在持续上传时，可以延后独立心跳，减少流量和串口占用。

## 8. P2：按平台要求实现

以下命令不需要在第一版固件中全部实现：

| 功能 | 命令 | 实现条件 |
|---|---|---|
| 设置超时和重发 | `1000` | 平台会下发时 |
| 查询/设置上传间隔 | `1061`-`1064` | 平台需要远程配置时 |
| 按时间范围查询历史数据 | `2031`/`2051`/`2061` | 平台主动查缺补漏时 |
| 完整请求应答/执行结果 | `9011`/`9012`/`9013` | 实现任何上位机下行命令时 |
| 原始周期性监测数据 | `2013` | 接入 VOCs/色谱等周期仪器时 |
| 噪声单次测量 | `2052` | 设备作为正式噪声监测设备时 |
| 自动标样核查 | `2062` | 传感器和平台明确支持时 |

## 9. P3：当前空气微站不实现

以下功能不属于当前空气微站范围，不建议占用 ESP32 的 Flash、RAM 和开发时间：

- 污染治理设施运行状态及日运行时间。
- 烟气工况值、折算浓度、污染物排放量。
- 炉膛温度、设施用电和关键生产工况。
- 污水采样、留样、即时留样。
- 远程反吹、即时采样、炉窑校验等污染源仪器控制。
- VOCs 谱图、图片、录音、视频等 HTTPS 多媒体文件传输。
- 数采仪与移动终端协议。
- 固定污染源生产工况标记和数据有效率判定。

## 10. ESP32-S3 实现约束和架构建议

### 10.1 只保留一套协议内核

建议拆分为：

```text
传感器原始数据
    -> 因子编码/单位转换
    -> 有效性和状态标记
    -> 分钟/小时/日统计
    -> 通用 CP 字段生成
    -> 2017/2025 版本封装
    -> 可选 SM4
    -> CRC/分包/发送/应答/补传
```

2017 和 2025 不应继续保持两份几乎相同的报文构建函数。

### 10.2 控制动态内存

- 对报文缓冲区设置明确上限。
- 优先使用固定容量缓冲区或可控的分段追加，避免频繁的 Arduino `String` 拼接造成堆碎片。
- 收包解析使用小型环形缓冲区和状态机。
- 补传队列在 Flash 中保存结构化数据，避免长期占用 RAM。

### 10.3 使用功能开关

建议至少保留以下编译或运行时开关：

```text
HJ212_ENABLE_2025
HJ212_ENABLE_SM4
HJ212_ENABLE_DOWNLINK_COMMANDS
HJ212_ENABLE_HISTORY_QUERY
HJ212_ENABLE_DEVICE_REGISTRATION
HJ212_ENABLE_HEARTBEAT
```

不同项目可以关闭未用模块，减少 Flash、RAM 和测试面积。

## 11. 建议开发阶段

### 阶段 A：2017 数据正确性（P0）

- `ST=22`。
- 2017 `Flag=5/4` 自动计算。
- O₃ 改为 `a05024`。
- 气体单位换算和按因子精度输出。
- 修正分钟/小时/日统计。
- 去除浓度因子的错误 `Cou`。
- 实现多状态数据标记。
- 完整校验 `9014` 应答。

### 阶段 B：2017 可靠性（P1）

- 配置化上传间隔、超时和重试。
- QN 唯一性。
- 1024 字符限制和分包。
- `1011/1012` 时间校准。
- 断网时新数据优先、历史数据限速补传。

### 阶段 C：2025 核心升级（P0-2025）

- 2025 `Flag=9/8` 自动计算。
- 新版数据标记，禁止全部硬编码为 `N`。
- `RF=1` 补传标志。
- SM4 加密。
- `1014` 密钥获取、更新和安全存储。

### 阶段 D：2025 平台兼容（P1/P2）

- `1001/1002/3019` 设备身份。
- `9015` 心跳。
- 按目标平台要求增加历史查询、远程间隔配置和执行结果应答。

## 12. 验收检查表

### 12.1 HJ 212-2017

- [ ] 报文为 `ST=22`。
- [ ] 需要应答且未分包时为 `Flag=5`。
- [ ] O₃ 使用 `a05024`。
- [ ] ppb/ppm 不会作为质量浓度数字直接上传。
- [ ] 每个因子使用独立精度。
- [ ] 小时数据使用全部有效分钟数据。
- [ ] 浓度因子不再上传伪 `Cou`。
- [ ] 异常数据不会被当作测量零值。
- [ ] `9014` 经过长度、CRC、QN、MN 和 CN 校验。
- [ ] 数据段超过 1024 字符时不会生成越界报文。

### 12.2 HJ 212-2025

- [ ] 需要应答且未分包时为 `Flag=9`。
- [ ] 传感器故障、校准、维护、超量程时不会上传 `Flag=N`。
- [ ] 公网数据命令按 2025 要求完成 SM4 加密。
- [ ] 密钥不会出现在日志、串口调试和明文配置中。
- [ ] 恢复上传的历史报文带 `RF=1`。
- [ ] 新采集数据的优先级高于历史补传。
- [ ] 平台要求时支持设备身份注册和 `9015` 心跳。

## 13. 最小可交付范围

考虑 ESP32-S3 资源和开发风险，建议将最小可交付范围定义为：

```text
HJ 212-2017：阶段 A + 阶段 B
HJ 212-2025：复用阶段 A/B + 阶段 C
平台专用功能：阶段 D 按需开启
```

这个范围可以保证空气微站的数据不被错误解释，具备必要的发送可靠性和 2025 公网安全能力，同时不需要实现庞大的污染源全命令集。
