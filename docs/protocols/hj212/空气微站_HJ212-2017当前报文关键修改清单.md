# 空气微站 HJ 212-2017 当前报文关键修改清单

## 1. 文档目的

本文档用于指导当前 ESP32-S3 空气微站修正 HJ 212-2017 上传报文。

当前阶段目标是先保证单包报文能够被平台正确解析、校验和解释，暂不实现分包，也不扩展与空气微站无关的污染源控制功能。

目标报文范围：

- `ST=22`：环境空气质量监测。
- `CN=2011`：实时数据。
- `CN=2051`：分钟数据。
- `CN=2061`：小时数据。
- `CN=2031`：日数据。
- `Flag=5`：HJ 212-2017、不分包、需要数据应答。

## 2. 已确定的因子代码

| 监测因子 | 使用代码 | 当前需要处理的问题 |
|---|---|---|
| 噪声 | `LA` | 当前错误使用了 `L90` |
| O₃ | `a05024` | 当前错误使用了 `w34011` |
| NO₂ | `a21004` | 保持不变 |
| CO | `a21005` | 保持不变 |
| SO₂ | `a21026` | 保持不变 |

### 2.1 噪声必须使用 `LA`

当前百叶箱寄存器 `502` 只返回一个实时噪声值，程序也只是读取当前值并进行普通平均，没有计算噪声百分位，因此不能将该数据命名为 `L90`。

实时数据应上传：

```text
LA-Rtd=56.8
```

HJ 212-2017 的噪声实时示例没有 `LA-Flag`，因此正常数据不需要增加：

```text
LA-Flag=N
```

字段之间仍需使用分号分隔。例如 LA 后面还有温度数据时：

```text
DataTime=20260902101644;LA-Rtd=56.8;a01001-Rtd=29.30,a01001-Flag=N
```

如果 LA 是 CP 数据区最后一个字段，则最后不加分号：

```text
DataTime=20260902101644;LA-Rtd=56.8&&
```

噪声采集失败时不要把故障当成 `0.0 dB` 上传。当前阶段可以不生成 LA 字段；只有目标平台明确支持时，才扩展使用 `LA-Flag=D`。

### 2.2 分钟、小时和日噪声

当前程序不能计算真正的 `L90`，因此分钟、小时和日数据中不得继续生成：

```text
L90-Data=57.5
```

当前阶段按已有普通统计值统一使用：

```text
LA-Data=57.5;LMx-Data=63.9;LMn-Data=54.1
```

上述 `LA-Data` 是当前窗口内已有算术平均值，不能命名为 `L90` 或 `Leq`。严格按
声学统计升级时，应按声能计算 `Leq`，再上传：

```text
Leq-Data=...;LMx-Data=63.9;LMn-Data=54.1
```

只有传感器直接提供 L90，或者程序使用足够密集的采样完成百分位统计后，才能重新增加 `L90-Data`。

## 3. P0：必须修改

### 3.1 修正 CRC 算法

当前 `calculateCRC()` 实现的是常规 Modbus CRC16：先将完整 CRC 寄存器与输入字节异或。

HJ 212-2017 附录 A 的示例算法要求先取 CRC 寄存器高位字节与输入字节异或：

```cpp
crc_reg = 0xFFFF;
for (每个数据段字节 byte) {
    crc_reg = (crc_reg >> 8) ^ byte;
    for (int j = 0; j < 8; ++j) {
        unsigned int check = crc_reg & 0x0001;
        crc_reg >>= 1;
        if (check == 0x0001) {
            crc_reg ^= 0xA001;
        }
    }
}
```

CRC 的计算范围仅为数据段：从 `QN=` 开始，到 CP 后面的第二个 `&&` 结束，不包含：

- 包头 `##`。
- 4 位长度字段。
- CRC 自身。
- 结尾 `\r\n`。

现有小时报文可作为测试向量：

| 项目 | 结果 |
|---|---|
| 数据段声明长度 | `1164` |
| 数据段实际长度 | `1164` |
| 当前 Modbus CRC | `0439` |
| HJ 212-2017 CRC | `5F00` |

注意：`5F00` 只适用于原始内容。修改字段、单位或空格后必须重新计算 CRC。

### 3.2 删除无意义的 `Cou`

当前程序将所有有效采样值的和写入 `Cou`，例如：

```text
a01001-Avg=29.13,a01001-Cou=262.20
a21005-Avg=366,a21005-Cou=3296
```

这些值只是采样值相加，不是累计排放量，对空气微站的温湿度、气体浓度、颗粒物、气象和噪声因子没有业务意义，必须删除。

修改前：

```text
a01001-Min=29.00,a01001-Avg=29.13,a01001-Cou=262.20,a01001-Max=29.30,a01001-Flag=N
```

修改后：

```text
a01001-Min=29.00,a01001-Avg=29.13,a01001-Max=29.30,a01001-Flag=N
```

当前小时数据共有 13 个 `Cou` 字段。删除这些字段并清理空格、末尾分号后，数据段可以降到 1024 字符以内，因此当前阶段可以暂不实现分包。

### 3.3 保留气体单位配置，换算覆盖全部报文类型

当前程序支持按因子配置 `ppb`、`ppm`、`ug/m3` 和 `mg/m3`，该能力继续保留，不在
固件中把气体上传单位硬编码为单一值。现场应根据目标平台对各因子的单位定义手动
选择对应单位。

空气微站没有特殊平台规定时，建议采用：

| 因子 | 原始单位 | 上传单位 | 建议小数位 |
|---|---|---|---|
| O₃ `a05024` | ppb | µg/m³ | 2 位 |
| NO₂ `a21004` | ppb | µg/m³ | 2 位 |
| SO₂ `a21026` | ppb | µg/m³ | 2 位 |
| CO `a21005` | ppb/ppm | mg/m³ | 3 位 |

当前气体换算是固定线性倍数。先统计原始值再分别换算 `Min/Avg/Max`，与先换算每个
采样再统计的数学结果一致，因此本次不修改小时统计逻辑。HJ 212组包时必须对实时、
分钟、小时和日数据的所有输出值应用同一单位配置：

```text
传感器原始ppb值
    -> 现有分钟/小时/日统计保持不变
    -> 组包时把Rtd/Min/Avg/Max换算成当前配置单位
    -> 按单位精度格式化
    -> 生成HJ 212字段
```

以当前小时数据为例，原始 CO 为 ppb 时：

```text
a21005-Avg=366
a21005-Max=781
```

换算后约为：

```text
a21005-Min=0.000,a21005-Avg=0.419,a21005-Max=0.895,a21005-Flag=N
```

当前 SO₂ 和 O₃ 示例换算后约为：

```text
a21026-Min=0.00,a21026-Avg=70.74,a21026-Max=639.29,a21026-Flag=N
a05024-Min=0.00,a05024-Avg=1.96,a05024-Max=13.74,a05024-Flag=N
```

HJ 212 报文本身不携带每个数值的单位，最终单位必须与目标平台的因子配置保持一致。

### 3.4 O₃上传统一为 `a05024`

为兼容设备中已经保存的FFat配置、LCD配置和历史SD记录，本次不全局重命名内部键。
内部旧键 `w34011` 在HJ 212输出边界统一映射成 `a05024`，实时、分钟、小时和日上传
均不得继续输出 `w34011`。组包器同时识别新旧键，且启动时不自动改写设备FFat。

### 3.5 清理数字前空格

ESP32 Arduino Core中的 `String(float, decimals)` 使用带最小字段宽度的 `dtostrf()`。
当 `ppb` 使用0位小数时，`0`、`1`等单字符值会被格式化成 `" 0"`、`" 1"`。
因此所有HJ 212数值必须改用无字段宽度的统一格式化入口。

禁止使用带宽度且默认右对齐的数值格式生成字段，例如：

```text
a21004-Min= 0
w34011-Avg= 1
```

必须输出：

```text
a21004-Min=0.00
a05024-Avg=1.96
```

所有因子使用同一个“无前导空格”的数值格式化入口，并根据因子选择小数位。

### 3.6 删除 CP 最后一个字段后的分号

当前循环为每个因子都追加 `;`，最终形成：

```text
...;a05024-Flag=N;&&
```

应改为：

```text
...;a05024-Flag=N&&
```

建议组包时使用“字段数组/字段追加器”：仅在两个字段之间添加分隔符，不在最后一个字段后添加分隔符。不要在组包完成后依赖字符串截断来补救。

### 3.7 长度字段必须最后计算

正确报文结构：

```text
## + 4位数据段长度 + 数据段 + 4位CRC + \r\n
```

生成顺序应为：

1. 生成完整 CP 数据区。
2. 生成从 `QN=` 到 CP 结束 `&&` 的完整数据段。
3. 将实际 ASCII 字符数格式化为 4 位十进制长度。
4. 对完整数据段计算 HJ 212 CRC。
5. 拼接包头、长度、数据段、CRC 和 `\r\n`。

不得先计算长度或 CRC，再继续修改字段内容。

当前阶段不实现分包，也不新增 `1024/950` 运行时硬拦截。删除无意义 `Cou` 后通过
测试确认当前因子组合的实时、分钟、小时和日报文长度；避免在没有分包能力时因硬
拦截直接丢弃完整业务报文。

### 3.8 保留普通因子的数据标记

污染物、颗粒物和气象因子继续使用自己的状态标记：

```text
a01001-Flag=N
a21005-Flag=N
```

至少保证：

- `N`：当前统计窗口内数据正常。
- `D`：传感器故障或无法正常测量。

通信失败或无有效采样不能转换成正常的数值 `0`。噪声 `LA-Rtd` 按HJ 212噪声实时示例不强制增加因子 Flag。

## 4. 当前可以保留的内容

以下内容在当前 2017 单包上传方案中可以继续使用：

```text
ST=22
Flag=5
CN=2011
CN=2051
CN=2061
CN=2031
```

时间规则：

- `2011` 的 `DataTime` 为本次采集时刻。
- `2051` 的 `DataTime` 为分钟统计窗口开始时刻。
- `2061` 的 `DataTime` 为小时统计窗口开始时刻。
- `2031` 的 `DataTime` 为日统计窗口开始时刻。

例如 10:01 生成 09:00 至 10:00 的小时数据时，使用：

```text
QN=20260902100111001
CN=2061
DataTime=20260902090000
```

该时间关系正确，不需要修改。

## 5. 建议修改位置

| 文件 | 主要修改 |
|---|---|
| `TSP/src/module/gas/GasUnitConverter.h` | 同时识别O₃新旧键，保留四种可配置上传单位 |
| `TSP/src/module/pack212/pack212.cpp` | 修正CRC、删除Cou、无空格格式化、输出键映射、删除末尾分号 |
| `TSP/src/app/dataManager/dataManager.h/.cpp` | 本次不修改，保持现有小时和日统计逻辑 |

旧配置兼容建议：

```text
读取旧配置 L90     -> 内部继续兼容 L90
读取旧配置 w34011  -> 内部继续兼容 w34011
启动加载            -> 不自动改写设备FFat
HJ212上传           -> 只输出 LA 和 a05024
```

## 6. 修改后的字段示例

### 6.1 实时数据片段

```text
DataTime=20260902101644;LA-Rtd=56.8;a01001-Rtd=29.30,a01001-Flag=N;a21004-Rtd=0.00,a21004-Flag=N;a21005-Rtd=0.419,a21005-Flag=N;a21026-Rtd=70.74,a21026-Flag=N;a05024-Rtd=1.96,a05024-Flag=N
```

### 6.2 小时数据片段

```text
DataTime=20260902090000;LA-Data=57.5;LMx-Data=63.9;LMn-Data=54.1;a01001-Min=29.00,a01001-Avg=29.13,a01001-Max=29.30,a01001-Flag=N;a21005-Min=0.000,a21005-Avg=0.419,a21005-Max=0.895,a21005-Flag=N;a21026-Min=0.00,a21026-Avg=70.74,a21026-Max=639.29,a21026-Flag=N;a05024-Min=0.00,a05024-Avg=1.96,a05024-Max=13.74,a05024-Flag=N
```

`LA-Data` 为当前阶段的兼容写法，正式接入前需要确认目标平台是否接受。若要求标准声学统计，应改为 `Leq-Data`，不能恢复使用未计算的 `L90-Data`。

### 6.3 日数据片段

当前程序已有 `CN=2031` 日数据分支，日数据使用与分钟、小时相同的字段规则：

```text
DataTime=20260902000000;LA-Data=57.5;LMx-Data=63.9;LMn-Data=54.1;a01001-Min=24.10,a01001-Avg=28.32,a01001-Max=31.20,a01001-Flag=N
```

该片段是字段结构示例。因日数据跨度较长，尚未取得修改后的完整实机日报文，需在
首次跨日运行测试中补充完整长度、CRC和平台应答记录。

## 7. 验收顺序

每生成一条报文，按以下顺序检查：

1. 检查因子代码：噪声为 `LA`，O₃ 为 `a05024`。
2. 检查数值单位：小时 `Min/Avg/Max` 与实时数据使用相同上传单位。
3. 检查字段：不存在无意义的 `Cou`。
4. 检查格式：不存在 `= 0` 等数字前空格。
5. 检查 CP：最后一个字段后不存在多余分号。
6. 检查实际数据段长度与 4 位长度字段完全一致。
7. 使用独立脚本按 HJ 212附录A重新计算 CRC，并与报文 CRC 对比。
8. 检查包尾严格为 `\r\n`。
9. 检查平台返回的 `9014` 应答与本次报文 QN、MN 对应。
10. 跨日后补充一条完整 `CN=2031` 实机报文验证记录。

## 8. 最小完成标准

- [ ] `L90` 已改为 `LA`。
- [ ] 实时报文使用 `LA-Rtd`，不强制增加 `LA-Flag=N`。
- [ ] 分钟、小时和日数据不再伪造 `L90-Data`。
- [ ] O₃ 已统一为 `a05024`。
- [ ] 四种气体上传单位继续可配置，实时、分钟、小时和日输出均按当前配置换算。
- [ ] 所有非累计监测因子均不再上传 `Cou`。
- [ ] 所有数字均无前导空格。
- [ ] CP 最后一个字段后无多余分号。
- [ ] 数据段长度按最终内容计算；当前阶段不增加分包和1024/950硬拦截。
- [ ] CRC 使用 HJ 212-2017 附录A算法，不再使用 Modbus CRC。
- [ ] 报文以 `\r\n` 结束。
- [ ] 普通因子的 `N/D` 状态来自真实采集状态，不把故障当作零值。
