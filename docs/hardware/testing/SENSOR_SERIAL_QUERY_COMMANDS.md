# TSP 传感器串口查询、回复解析与统一测试工具规范

## 1. 适用范围

本文档描述当前正式固件使用的传感器查询方式、Modbus RTU请求帧、回复帧解析、数值换算和有效性判断，可用于制作统一的Windows串口测试工具。

适用源码：

- standard：`firmware/standard/TSP`，版本`2.1.0`
- certified：`firmware/certified/TSP`，版本`2.1.0.1`

本文档只列出读取命令，不包含修改地址、校准、量程设置或其他写寄存器命令。

需要特别注意：

- standard和certified的传感器查询帧相同。
- 两者的原始回复解析相同。
- certified对O3、NO2、SO2存在专用的500 ppb输出上限，详见第8.6节。
- 当前气体读取已经改为从`0x6000`开始一次读取2个寄存器；旧文档中只读`0x6001`的命令不再代表当前固件。

## 2. 测试安全要求

### 2.1 避免两个Modbus主站同时工作

串口测试工具和TSP MCU都是Modbus主站。线下测试实际传感器时，不要让二者同时向同一总线发送请求，否则可能出现帧碰撞、CRC错误、超时或错误归因。

推荐方式：

1. 一次只连接一个待测传感器。
2. 将传感器通信线从TSP主板隔离，或者确保MCU没有在该总线上轮询。
3. 使用USB-RS485或3.3 V USB-TTL适配器直接查询传感器。
4. 传感器仍需按其说明书提供正确的工作电源。

### 2.2 供电和接线

- USB-RS485适配器只连接A、B和必要的公共GND，不要把适配器VCC接入主板12 V传感器端口。
- 颗粒物TTL为3.3 V逻辑，USB-TTL适配器不得输出5 V逻辑。
- TTL必须交叉连接：工具TX接传感器RX，工具RX接传感器TX。
- RS485完全无回复时，应断电后检查A/B极性；不同厂家的A/B、D+/D-命名可能相反。

## 3. 串口和协议参数

RS485环境/气体总线与颗粒物TTL端口均使用以下参数：

| 参数 | 设置 |
|---|---|
| 协议 | Modbus RTU |
| 波特率 | 9600 |
| 数据位 | 8 |
| 校验 | None |
| 停止位 | 1 |
| 流控 | None |
| 读取功能码 | `0x03`，Read Holding Registers |
| 发送模式 | HEX |
| 回车换行 | 不附加 |

端口分组：

| 端口 | 传感器 |
|---|---|
| RS485 A2/B2 | 风速、风向、百叶箱温湿度/噪声/气压、O3、NO2、CO、SO2 |
| TTL | PM1、PM2.5、PM10、TSP颗粒物模块 |
| I2C | 板载SHT30，不适用本文串口命令 |

## 4. Modbus RTU基础规则

### 4.1 查询帧

功能码`0x03`的查询帧格式：

```text
[从站地址] [03] [起始地址高] [起始地址低] [数量高] [数量低] [CRC低] [CRC高]
```

本文全部寄存器地址均为Base 0地址。例如：

- Base 0地址0对应部分软件显示的`40001`。
- Base 0地址500对应部分软件显示的`40501`。
- 制作工具时建议直接保存和显示Base 0地址，避免PLC Address偏移一位。

### 4.2 正常回复帧

正常回复格式：

```text
[从站地址] [03] [数据字节数] [数据...] [CRC低] [CRC高]
```

数据字节数应等于：

```text
寄存器数量 * 2
```

每个16位寄存器的数据字节顺序为高字节在前、低字节在后：

```text
register = (dataHigh << 8) | dataLow
```

### 4.3 异常回复帧

Modbus异常回复通常为：

```text
[从站地址] [83] [异常码] [CRC低] [CRC高]
```

工具必须把异常回复与超时、CRC错误、正常数值0区分开，不能把通信失败自动解释成传感器数值0。

### 4.4 CRC16

Modbus CRC16初值为`0xFFFF`，多项式为`0xA001`。帧内CRC低字节先发送、高字节后发送。

伪代码：

```text
crc = 0xFFFF
for byte in frame_without_crc:
    crc = crc XOR byte
    repeat 8 times:
        if crc bit0 == 1:
            crc = (crc >> 1) XOR 0xA001
        else:
            crc = crc >> 1

append crc low byte
append crc high byte
```

工具收到回复后必须先校验CRC，再解析寄存器。

## 6. 环境传感器回复解析

环境传感器均读取1个16位寄存器，正常回复固定为7字节：

```text
[slave] 03 02 [dataHigh] [dataLow] [crcLow] [crcHigh]
```

### 6.1 风速

查询：

```text
01 03 00 00 00 01 84 0A
```

计算：

```text
raw = uint16(dataHigh, dataLow)
windSpeed_mps = raw / 100.0
```

示例回复：

```text
01 03 02 01 5E 38 2C
```

其中`0x015E = 350`：

```text
350 / 100 = 3.50 m/s
```

当前固件把`0xFFFF`判为无效；原始值0可以表示0.00 m/s。

### 6.2 风向

查询：

```text
01 03 00 01 00 01 D5 CA
```

计算：

```text
raw = uint16(dataHigh, dataLow)
windDirection_degree = raw / 100.0
```

示例回复：

```text
01 03 02 23 28 A1 6A
```

其中`0x2328 = 9000`：

```text
9000 / 100 = 90.00 degree
```

当前固件把`0xFFFF`判为无效。

### 6.3 湿度

查询：

```text
02 03 01 F4 00 01 C4 37
```

计算：

```text
raw = uint16(dataHigh, dataLow)
humidity_percent = raw / 10.0
```

示例回复：

```text
02 03 02 02 8A 7C 83
```

其中`0x028A = 650`：

```text
650 / 10 = 65.0 %
```

当前固件把`0xFFFF`判为无效。

### 6.4 温度

查询：

```text
02 03 01 F5 00 01 95 F7
```

温度必须按有符号16位整数解释：

```text
rawUnsigned = uint16(dataHigh, dataLow)
rawSigned = int16(rawUnsigned)
temperature_celsius = rawSigned / 10.0
```

正温示例：

```text
回复：02 03 02 00 FD 3D C5
0x00FD = 253
253 / 10 = 25.3 C
```

负温示例：

```text
回复：02 03 02 FF CE 3C 20
0xFFCE按int16解释为-50
-50 / 10 = -5.0 C
```

当前固件有效原始范围为`-400～1200`，对应`-40.0～120.0 C`；超出范围判为无效。

### 6.5 噪声

查询：

```text
02 03 01 F6 00 01 65 F7
```

计算：

```text
raw = uint16(dataHigh, dataLow)
noise_dB = raw / 10.0
```

示例回复：

```text
02 03 02 02 8F BC 80
```

其中`0x028F = 655`：

```text
655 / 10 = 65.5 dB
```

当前固件把原始值`0`和`0xFFFF`判为无效。

当前寄存器只提供一个实时噪声值，不能仅凭该值计算真正的L90或Leq。工具界面建议显示为“实时噪声/LA兼容值”，不要把它解释成已经完成统计的L90。

### 6.6 气压

查询：

```text
02 03 01 F9 00 01 55 F4
```

计算：

```text
raw = uint16(dataHigh, dataLow)
pressure_kPa = raw / 10.0
```

示例回复：

```text
02 03 02 03 E8 FC FA
```

其中`0x03E8 = 1000`：

```text
1000 / 10 = 100.0 kPa
```

当前固件规则：

1. `0xFFFF`无效。
2. 物理有效范围为`30.0～120.0 kPa`。
3. 第一个物理范围内的值直接接受。
4. 与上次有效值差值不超过`1.5 kPa`时直接接受。
5. 跳变超过`1.5 kPa`时，候选值需要连续3个采集周期稳定在`±0.3 kPa`内才接受。
6. 当前源码每个采集周期读取一次气压；通信失败时才进行最多3次通信尝试。

统一工具建议同时显示“本次原始气压”和“按固件跳变策略接受后的气压”，便于区分传感器变化与固件过滤结果。

## 7. 颗粒物四通道回复解析

### 7.1 查询和回复长度

查询：

```text
01 03 00 10 00 08 45 C9
```

读取8个16位寄存器，正常回复共21字节：

```text
01 03 10 [16字节寄存器数据] [CRC低] [CRC高]
```

其中字节数`0x10`表示后续有16个数据字节。

### 7.2 通道映射

每个颗粒物通道占两个连续16位寄存器，组成一个32位无符号整数：

```text
value = (highRegister << 16) | lowRegister
```

| 传感器 | ID | 高16位寄存器 | 低16位寄存器 |
|---|---|---:|---:|
| PM1 | `a34005` | R16 | R17 |
| PM2.5 | `a34004` | R18 | R19 |
| PM10 | `a34002` | R20 | R21 |
| TSP | `a34001` | R22 | R23 |

### 7.3 完整示例

示例回复：

```text
01 03 10
00 00 00 0C
00 00 00 19
00 00 00 28
00 00 00 14
32 0C
```

去掉换行后的完整帧：

```text
01 03 10 00 00 00 0C 00 00 00 19 00 00 00 28 00 00 00 14 32 0C
```

计算结果：

```text
PM1   = (0x0000 << 16) | 0x000C = 12 ug/m3
PM2.5 = (0x0000 << 16) | 0x0019 = 25 ug/m3
PM10  = (0x0000 << 16) | 0x0028 = 40 ug/m3
TSP   = (0x0000 << 16) | 0x0014 = 20 ug/m3
```

当前固件默认单位为`ug/m3`。如果设备配置单位发生变化，固件使用以下比例：

| 配置单位 | 输出值 |
|---|---|
| `ug/m3` | `raw * 1` |
| `mg/m3` | `raw * 0.001` |
| `ng/m3` | `raw * 1000` |

当前源码只把组合值`0xFFFFFFFF`判为传感器无效；组合值`0`会作为合法零浓度处理。工具应同时保留原始32位值，避免单位换算后无法追溯。

## 8. 气体模块回复解析

### 8.1 寄存器含义

气体模块一次读取两个16位寄存器：

| 寄存器 | 含义 |
|---:|---|
| `0x6000` | 状态字 |
| `0x6001` | 浓度原始值，当前固件按ppb解释 |

正常回复固定为9字节：

```text
[slave] 03 04 [statusHigh] [statusLow] [valueHigh] [valueLow] [crcLow] [crcHigh]
```

解析：

```text
status = (statusHigh << 8) | statusLow
rawPpb = (valueHigh << 8) | valueLow
```

### 8.2 四气体查询帧

```text
NO2：04 03 60 00 00 02 DA 5E
CO ：05 03 60 00 00 02 DB 8F
SO2：06 03 60 00 00 02 DB BC
O3 ：03 03 60 00 00 02 DB E9
```

### 8.3 正常回复示例

SO2状态就绪、浓度8 ppb：

```text
06 03 04 80 00 00 08 A4 F5
```

解析：

```text
status = 0x8000
rawPpb = 0x0008 = 8 ppb
```

NO2状态就绪、浓度11 ppb：

```text
04 03 04 80 00 00 0B C7 34
```

CO状态就绪、浓度725 ppb：

```text
05 03 04 80 00 02 D5 56 CC
```

### 8.4 状态字解析

当前固件使用的状态位：

| 位 | 掩码 | 含义 | 当前固件结果 |
|---:|---:|---|---|
| Bit15 | `0x8000` | 预热完成/数据就绪 | 未置位时判`D` |
| Bit6 | `0x0040` | 高浓度保护 | 判`T` |
| Bit5 | `0x0020` | 传感器丢失或损坏 | 判`D` |
| Bit4 | `0x0010` | 超量程 | 判`T` |
| Bit3 | `0x0008` | TWA报警 | 工具应单独显示；当前固件不因此改变N/D/T |
| Bit2 | `0x0004` | STEL报警 | 工具应单独显示；当前固件不因此改变N/D/T |

当前固件状态分类优先级：

```text
if Bit15 == 0 or Bit5 == 1:
    flag = D
else if Bit6 == 1 or Bit4 == 1:
    flag = T
else:
    flag = N
```

常见状态：

| 状态 | 解释 | 当前固件Flag |
|---:|---|---|
| `0x8000` | 就绪，无故障 | `N` |
| `0x0000` | 未就绪 | `D` |
| `0x8020` | 就绪但传感器故障 | `D` |
| `0x8040` | 高浓度保护 | `T` |
| `0x8010` | 超量程 | `T` |

当Bit15为0时，供应商资料说明低15位可能用于预热倒计时，时间单位为0.1秒。工具应同时显示完整状态十六进制值和低15位值，不要只显示“异常”。

### 8.5 `0x0000`复读规则

未就绪示例：

```text
03 03 04 00 00 00 00 D9 F3
```

当前固件处理方式：

```text
首次读取通信成功
→ Bit15未置位
→ 等待共享气体事务间隔至少500ms
→ 向同一从站再次发送相同的0x6000/2寄存器查询
→ 使用第二次成功回复的状态和浓度
```

如果第二次仍未就绪，则最终标记为`D`。统一工具应记录第一次和第二次回复，不能只保留最终值，否则无法分析状态恢复率。

### 8.6 气体浓度单位换算

传感器原始浓度按ppb解释。通用换算：

```text
ppm = ppb / 1000
ug/m3 = ppb * massFactor
mg/m3 = ppb * massFactor / 1000
```

当前固件质量浓度系数：

| 气体 | massFactor | 默认输出单位 | 默认换算 |
|---|---:|---|---|
| O3 | 1.96319 | `ug/m3` | `ppb * 1.96319` |
| NO2 | 1.88180 | `ug/m3` | `ppb * 1.88180` |
| CO | 1.14560 | `mg/m3` | `ppb * 1.14560 / 1000` |
| SO2 | 2.62004 | `ug/m3` | `ppb * 2.62004` |

例如SO2原始值8 ppb：

```text
8 * 2.62004 = 20.96032 ug/m3
```

例如CO原始值725 ppb：

```text
725 / 1000 = 0.725 ppm
725 * 1.14560 / 1000 = 0.83056 mg/m3
```

certified专用规则：

- O3、NO2、SO2在进入单位换算前，ppb值最大限制为500。
- CO不应用该500 ppb限制。
- standard不应用上述500 ppb限制。

统一工具建议同时显示：

1. 传感器原始ppb。
2. standard计算值。
3. certified计算值。
4. 当前选择单位下的最终值。
5. 状态Flag和所有状态位。

## 9. 当前固件重试和间隔

### 9.1 普通环境传感器和颗粒物

| 项目 | 当前值 |
|---|---:|
| 最大通信尝试次数 | 3 |
| 单次响应超时 | 500 ms |
| 通信重试/查询间隔 | 300 ms |

### 9.2 气体传感器

| 项目 | 当前值 |
|---|---:|
| 相邻气体Modbus事务最小间隔 | 500 ms |
| 首次查询最大通信尝试次数 | 3 |
| 单次响应超时 | 500 ms |
| 通信成功但Bit15未置位 | 500 ms后复读一次 |
| 状态复读的通信尝试次数 | 1 |

通信重试和状态复读是两个不同概念：

- 通信重试：没有有效Modbus回复，例如超时、CRC错误。
- 状态复读：已经收到CRC正确的正常回复，但状态寄存器显示未就绪。

统一工具必须分别统计这两类情况。

## 10. 建议的工具解析流程

每次查询建议执行以下步骤：

```text
1. 清理本次请求之前遗留的接收缓冲区。
2. 记录发送时间和完整request_hex。
3. 发送Modbus RTU查询帧。
4. 等待完整回复或超时。
5. 校验最小长度。
6. 校验从站地址。
7. 检查功能码是否为异常功能码。
8. 校验功能码和数据字节数。
9. 校验CRC16。
10. CRC正确后再解析寄存器。
11. 保存原始寄存器值。
12. 执行传感器专用换算和有效性判断。
13. 记录通信重试序号、状态复读序号和响应耗时。
14. 等待规定间隔后查询下一传感器。
```

不应采用以下处理：

- 超时后直接返回数值0。
- CRC错误后仍解析浓度。
- 只保存最终工程值，不保存原始报文。
- 把气体`0x0000`和Modbus无回复归为同一种错误。
- 在MCU仍轮询时，让测试工具同时作为第二个主站发送命令。

## 12. 推荐的线下测试方法

### 12.1 单模块地址确认

1. 每次只连接一个模块。
2. 对该类型所有可能从站地址各发送一次查询。
3. 记录唯一有正常回复的地址。
4. 将物理模块标签、气体类型和从站地址建立固定映射。
5. 确认不存在两个模块使用相同从站地址。

气体预期地址：

```text
O3  = 3
NO2 = 4
CO  = 5
SO2 = 6
```

### 12.2 气体稳定性测试

建议每个气体模块单独测试10～20分钟：

1. 发送对应的`0x6000`、数量2查询。
2. 查询间隔使用500 ms。
3. 统计总查询数、通信失败数、`0x8000`次数和`0x0000`次数。
4. 遇到`0x0000`时，再等待500 ms复读一次并保留两次回复。
5. 不要只统计最终恢复后的结果。

### 12.3 颗粒物测试

1. 颗粒物模块通过TTL连接。
2. 气泵通气达到测试要求后，在气泵仍运行期间发送四通道批量查询。
3. 检查回复字节数是否为`0x10`。
4. 分别解析四个32位通道。
5. 连续记录时应保留泵开启时间、查询时间和响应时间。

### 12.4 完整轮询测试

如果工具需要模拟当前固件轮询，推荐顺序为：

```text
非气路阶段：环境传感器
气路阶段：颗粒物四通道批量读取
气路阶段：NO2 → CO → SO2 → O3
```

气体之间保持至少500 ms事务间隔。这里的事务间隔指上一笔事务结束到下一笔事务开始的时间，不是简单从两次发送时间戳相减。

## 13. 可选传感器

当前源码支持TVOC采集器，但默认14因子配置未启用。仅在设备配置明确启用TVOC时使用：

```text
Slave：3
起始地址：0x0001
寄存器数量：3
查询：03 03 00 01 00 03 55 E9
```

因为当前O3默认同样使用Slave 3，所以不能在同一RS485总线上同时使用默认地址的TVOC和O3。启用前必须确认硬件地址和项目配置，避免地址冲突。
