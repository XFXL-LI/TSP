# Firmware 2.1.7 变更记录

- 最后更新：2026-10-23
- Variant：standard
- 构建状态：`compiled-not-hardware-verified`
- 上一版本：[standard 2.1.6](CHANGELOG_2.1.6.md)

## 主要变化

- 取消每次启动的30/60/30分钟SD自动对照，恢复历史、pending、查询、扫描和挂载重试的
  持续正常业务。原文件、配置和统计窗口沿用既有逻辑，旧诊断版跳过的历史不补写。
- `SdIoDiagnostics`改为被动在途计数：启动为Normal，没有定时阶段转换，`blocked()`
  始终为false；保留调用接口以兼容既有入口，SD互斥锁及OTA业务互斥继续生效。
- 默认日志从DEBUG改为INFO。LED逐帧/缓存、正常传感器查询、JSON收发回显、对象释放、
  采集/处理阶段及详细UART/SD过程不再默认刷屏，相关DEBUG调用仍保留用于调试构建。
- 保留`COLLECT`、`TX_RESULT`、`STORE`及待传排队/实际保存结果；正常UART保护详情
  `HJ_UART_TX/CONTEXT`、`HJ_PRIORITY_RESTORE`及SD begin/end改为DEBUG，保护检查继续执行。
- 保留并补充异常提示：短写、实际保护不足、基础等级恢复不符、最终传感器状态无效和
  LED写入失败。LED失败沿用原有5秒重试节奏，正常显示及50 ms帧间隔不变。
- SD操作实际返回时，逻辑作用域耗时至少3000 ms记录`SD_IO_SLOW`。它不终止SDK调用，
  不能把此提示解释成底层硬超时或SD持久化校验成功。

继承[2.1.6](CHANGELOG_2.1.6.md)的实际优先级保护、
[2.1.4](CHANGELOG_2.1.4.md)的有界异步待存及臭氧出口`w34011`。
120秒采集、70秒气泵、9600波特率、3000 ms包间隔、Flag/ACK/重试策略和LCD/LED
业务协议保持原样，没有新增队列、任务或持久化开关，不自动把现有Flag改成5。

## 验证结果

- 两版当前源码上传回归通过，覆盖实际优先级继承与恢复、短写/拒写、Flag=4/5、ACK、
  重试和忙时让路、SET+SAVE、CSQ/校时、臭氧兼容及有界待存故障路径。
- 持续SD回归实际调用存储/查询/待存入口，在原对照边界、模拟48小时和计时回绕下均
  正常受理；还覆盖四类历史数据、挂载/原始入口、并行操作在途计数和慢操作告警。
- 两版各19组控制回归通过，覆盖LED持续显示、帧间隔、开关/清屏/失败重试、队列背压、
  加热并发控制；气体/SD挂载故障及get_data兼容和容量回归通过。
- 主机测试中的48小时是模拟时钟推进，不是实机长跑。两版编译通过，构建前后源码指纹
  一致；本版尚未取得新的实机接收或历史文件可读性验收。

## 已知问题与使用范围

此前certified 2.1.6.1现场实时有效接收约99%，仍有缺头、乱码和未匹配报文。
本版保留发送保护并恢复正常存卡，不能据编译/主机结果宣称已消除所有端到端掉数。

小时/日历史文件“写入报告成功、查询提示传感器ID为空”的问题仍待查。本版不改记录
格式或历史解码，恢复持续存卡并不证明这些文件已能正确读回。已有SDK阻塞、SD失败
或待存队列满时，仍不能保证新历史/待传项持久化。后续验证继续保留MCU结果日志、
服务器有效报文及覆盖同一时间段的未过滤原始TCP数据。
