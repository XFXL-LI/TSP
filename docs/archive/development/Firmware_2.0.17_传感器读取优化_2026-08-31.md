# Firmware 2.0.17 三类传感器读取优化记录

日期：2026-08-31  
状态：源码已修改、编译通过、尚未烧录和实机验证

## 修改目的

降低SDS069颗粒物、XM8189风速风向和从机2气象百叶箱的无效重复查询，满足颗粒物
技术人员提出的查询间隔不短于200 ms要求，并给当前485链路留出更稳妥的300 ms间隔。

## 实施内容

统一策略定义在：

`src/app/collectorManager/collect/SensorReadPolicy.h`

- 正常读取：每个已启用因子查询一次。
- 响应超时：500 ms。
- 失败重试：最多3次尝试，重试间隔300 ms。
- 查询间隔：每次事务结束后保持300 ms再释放对应串口互斥锁。
- 因子禁用：沿用原有选择逻辑，不会为未启用因子发送查询。

涉及采集器：

- 颗粒物：PM1、PM2.5、PM10、TSP。
- 风传感器：风速、风向。
- 气象百叶箱：湿度、温度、噪声、气压。

未调整传感器从机地址、波特率、寄存器和单位换算。当前实际气象设备继续按项目已有
从机2、9600波特率工作；说明书默认值只用于新设备配置核对，不覆盖现场参数。

## 读取负荷变化

在十个因子全部启用时：

- 修改前且通信均成功：约56条Modbus命令/分钟。
- 修改后且首次通信成功：10条Modbus命令/分钟。
- 修改后十项全部连续失败：最多30条Modbus命令/分钟。

颗粒物约一分钟才更新一次数据，因此取消同一分钟内两次读取平均不会损失独立样本。
气压原来的5次同秒中值采样被取消，但30～120 kPa范围判断和跨分钟突变确认保留。

## 实机验收建议

1. 烧录后确认启动版本仍为2.0.17，且14个启用因子都能完成分钟采集。
2. 连续观察至少2小时，比较`Modbus bulk read failed`、`slave=2`、`register=500/501/502/505`
   的告警数量，预期不再持续密集出现。
3. 人为断开一个传感器，确认日志最多出现`attempt=1/3`至`attempt=3/3`，该因子本次无效，
   其他因子仍继续；恢复接线后下一轮应自动恢复，无需重启。
4. 临时禁用一个颗粒物或气象因子，确认它不出现在分钟数据中，其他已启用因子正常。
5. 做一次四气体`start/status/zero/cancel/finish`回归，允许短暂`bus_waiting`，但不得持续，
   用于确认新增300 ms串口间隔没有破坏校准会话。
6. 最后运行24～48小时，检查无重启、看门狗、崩溃、SD保存失败、持续内存下降或HJ212
   长时间中断。

仅凭编译通过不能代替传感器实机验证；精确确认命令间隔可使用485/TTL串口分析仪抓包。
