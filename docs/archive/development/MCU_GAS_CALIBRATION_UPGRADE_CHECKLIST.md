## 1. 已确认需求

1. O3、NO2、CO、SO2 分别使用独立 LCD 校准页面。
2. 四气体执行真正的两点校准：零点 `0x1000`，量程点 `0x1001`。
3. 写标定命令后轮询 `0x6006`；返回 `0x0001` 才代表该标定点成功。
4. LCD 只显示当前浓度值 `ppb` 和操作状态。
5. LCD 不显示、不读取、不修改 MCU 内部量程点目标。
6. 量程点请求不能把当前显示浓度作为目标值。
7. MCU 内部预设目标：O3/NO2/SO2 为 500 ppb，CO 为 5000 ppb。
8. 正常 60 秒四气体采集只读取 `0x6001`，不再使用 `0x6000` 判断日常浓度是否有效。
9. 正常 Modbus 读取成功即认为浓度有效，`0` 是有效浓度；通信失败才是本次无效。
10. 校准期间四气体维护数据不进入正常统计、存储和 HJ212，其他因子继续运行。
11. 正常 60 秒 485 采集优先于校准页面高频浓度刷新。
12. 校准任务不能在通气等待、稳定等待或状态轮询间隔中持续持有 485 锁。
13. 量程点成功后继续保持校准模式，完成洁净空气清洗并收到 LCD `finish` 后才恢复业务数据。
14. 量程点使用最近 20 秒平均值执行目标偏差 ±20% 防误操作判断，并向 LCD 提供稳定性提示。
15. 旧 `gal_data` 的四气体校准调用禁用，颗粒物原有校准保持不变。
16. 四气体目标保存在 MCU 本地管理员配置中。
17. 新 `gas_calibration` 全部动作要求管理员权限。
18. 校准成功后不重启 MCU，实施版本号为 2.0.15。

## 2. 2.0.14 旧实现与 2.0.15 目标差异

## 2.1 当前气体日常采集

当前四个采集器一次读取 `0x6000` 起始的两个寄存器：

```text
0x6000 状态
0x6001 浓度
```

现有逻辑会因预热位、故障位、保护位或超量程位将浓度标为无效。

目标逻辑：

```text
FC03读取0x6001，数量1
→ 通信成功：DataPacket有效，值为寄存器整数ppb
→ 通信失败：DataPacket无效
```

不对 0 值做无效判断，不按项目文本量程钳制浓度。

## 2.2 当前气体 `gal_data`

当前 `gal_data` 接收 `DATA/RATIO`，但四气体采集器忽略两个参数，分别使用硬编码帧：

```text
解保护
→ 写0x6006 = [0x1000, 0x0000]
→ 只确认写应答
→ 立即返回galRes=true
```

当前没有量程点 `0x1001`，也没有读取 `0x6006` 最终状态。

目标逻辑新增独立 `gas_calibration` 会话接口，不再用 `DATA/RATIO` 表达气体两点校准。

## 3. 已新增模块

已新增：

```text
src/module/gas/GasCalibrationManager.h
src/module/gas/GasCalibrationManager.cpp
```

已实现职责：

- 保存唯一活动校准会话；
- 保存气体 ID、从站、状态、最近浓度和时间；
- 从本地校准配置加载并在会话开始时锁定量程点目标；
- 保存最近 20 秒的固定长度浓度样本和稳定性提示；
- 管理每 2 秒浓度读取；
- 管理解保护、零点和量程点写命令；
- 管理每 1 秒 `0x6006` 状态查询；
- 管理 LCD 心跳、30 分钟会话超时和恢复；
- 提供四气体维护隔离状态；
- 提供正常 485 采集优先协调状态；
- 生成固定大小、可查询的会话快照。

内部使用枚举而不是动态字符串保存状态：

```cpp
enum class GasCalibrationState : uint8_t {
    IDLE,
    ZERO_WAIT,
    ZERO_EXECUTING,
    SPAN_WAIT,
    SPAN_EXECUTING,
    PURGING,
    CANCEL_PURGING,
    TIMED_OUT,
    FAILED
};
```

内部只允许一个会话，气体可使用枚举或固定索引，不在循环中动态分配对象。

## 4. MCU 本地校准配置

四气体量程目标不写死为编译常量，保存在 MCU 本地独立文件：

`/gasCalibration.json`

默认配置如下：

```json
{
  "span_targets_ppb": {
    "w34011": 500,
    "a21004": 500,
    "a21005": 5000,
    "a21026": 500
  },
  "max_deviation_percent": 20,
  "stability_window_seconds": 20,
  "min_stability_samples": 10,
  "stability_tolerance_percent": 5
}
```

配置规则：

- 配置修改必须经过管理员权限校验；LCD 校准页无权在 `span` 请求中携带或覆盖目标值。
- `gas_calibration` 状态响应不返回目标浓度，LCD 页面保持目标值不可见。
- `span` 命令只提交操作意图，MCU 从本地配置取得当前气体目标值并写入模组。
- 配置采用临时文件写入、回读校验、原子替换，避免掉电留下半文件。
- 配置缺失时可创建上述默认配置；已有配置格式错误、目标越界或校验失败时，禁止开始校准并返回 `calibration_config_invalid`，不得静默使用不确定目标。
- 活跃校准会话期间禁止修改配置；会话在 `start` 时锁定本次目标，修改后的配置从下一次会话生效，不需要重启 MCU。
- 2.0.15 未向 LCD 校准页面开放目标配置读写动作；管理员后续配置界面必须另行按上述规则对接。

## 5. Modbus 命令实现

## 5.1 正常浓度读取

四个气体采集器改为：

```cpp
readModbusRegs(slave, 0x6001, 1, &value, ...)
```

要求：

- 一次成功立即返回；
- 正常 60 秒采集可以保留失败重试策略；
- 通信成功且值为 0 时仍设置 `is_valid=true`；
- 删除基于 `0x6000` 的预热、保护、故障和超量程无效判定；
- 日志不再把 `0x6000=0x0000` 解释为日常浓度无效原因。

## 5.2 校准页面浓度读取

在 `ZERO_WAIT`、`SPAN_WAIT`、`PURGING`、`CANCEL_PURGING` 状态：

- 每 2 秒尝试读取目标气体 `0x6001` 一次；
- 每次只进行一次 Modbus 尝试，失败后释放锁，下一周期再读；
- 成功后更新 `current_ppb`、`last_read_ms` 和 `fresh`；
- 失败时不把缓存改成 0；超过新鲜度期限后返回 `fresh=false`；
- 仅供 LCD 校准页面显示，不进入 DataManager。

## 5.3 解保护

使用现有 `writeModbusRegs()` 或统一写寄存器辅助函数动态生成协议帧：

```text
地址：0x4FFF
数量：1
数据：0x55AA
```

必须校验完整 Modbus 写应答、从站、功能码、地址、数量和 CRC，不能只比较前 4 字节。

## 5.4 零点命令

```text
地址：0x6006
数量：2
数据0：0x1000
数据1：0x0000
```

零点命令参数值不参与标定计算。

## 5.5 量程点命令

```text
地址：0x6006
数量：2
数据0：0x1001
数据1：profile.spanTargetPpb
```

示例：

```text
O3/NO2/SO2：0x1001, 0x01F4
CO：         0x1001, 0x1388
```

帧和 CRC 必须动态生成，不继续维护四套硬编码字节数组。

## 5.6 标定状态读取

写命令收到有效应答后：

- 立即释放 485 锁；
- 暂停 `0x6001` 高频读取；
- 每 1 秒申请一次 485 锁，读取 `0x6006` 数量 1；
- 每次读取结束立即释放锁；
- 最长建议 120 秒；
- 正常采集占用 485 时本次查询延后，不记作模组失败。

状态映射：

| 值 | MCU 处理 |
| ---: | --- |
| `0x0000` | 继续等待 |
| `0x0001` | 当前标定点成功 |
| `0x0002` | 当前标定点失败 |
| `0x0003` | 不支持，失败 |
| `0x0004` | 参数无效，失败 |
| `0x0005` | 模组执行超时，失败 |
| `0x0100`～`0x0103` | 执行步骤，继续等待 |
| 其他值 | 记录未知状态，继续有限次数或按协议失败 |

连续状态读取通信失败建议达到 3 次后标记 `status_read_failed`，但不把单次 485 忙当成通信失败。

## 6. 485 锁和优先级

## 6.1 事务级持锁

所有校准操作继续使用 `SerialManager::getMutex(SERIAL_485)`。

持锁范围只覆盖：

```text
清理接收缓存
→ 发送一帧
→ 等待并读取这一帧响应
→ 校验
→ 释放锁
```

禁止在以下过程持锁：

- 等待零气或标气稳定；
- 等待 LCD 操作；
- 两次浓度读取之间的 2 秒；
- 两次 `0x6006` 查询之间的 1 秒；
- 清洗计时；
- LCD 心跳等待。

## 6.2 解保护和写标定的短临界区

解保护与紧随其后的写标定命令需要避免其他 Modbus 事务插入。建议作为一个有上限的短临界区：

```text
取得485锁
→ 解保护并确认
→ 必要的短间隔
→ 写标定并确认
→ 释放485锁
```

该区间必须小于正常采集当前 3 秒锁等待上限。现有代码的 1 秒固定间隔是否保留，应在实机测试中确认；不能无依据延长。

## 6.3 正常采集优先协调

增加原子标志或等价协调接口：

```text
normal_485_pending
```

在 `collectorManager.poll()` 正常 60 秒采集开始前置位，完成后清除。

规则：

1. 校准任务准备发起浓度或状态读取前先检查该标志。
2. 标志已置位时跳过本次低优先级读取，保留缓存，不能抢锁。
3. 校准任务已经进入一笔 Modbus 事务时允许完成并释放。
4. 校准任务已经进入“解保护+写标定”短临界区时允许完整结束。
5. LCD 在正常采集期间点击校准时，会话状态显示等待总线，正常采集结束后再执行。
6. 等待总线不计作 `unlock_failed` 或 `status_read_failed`。

建议优先级：

```text
正常60秒485采集
  > 已开始的解保护+写标定短临界区
  > 0x6006状态读取
  > 0x6001校准页面刷新
```

## 7. 校准会话和任务

## 7.1 复用现有任务

2.0.15 复用当前常驻 `CollectGalTask`：

- 保留现有 4 KB 栈，实施后根据高水位日志判断是否需要调整；
- 不新增临时 FreeRTOS 任务；
- 不在每次页面进入时创建/删除任务；
- 将现有 `galpoll()` 扩展为事件处理加会话 `tick()`，或由同一循环调用两者。

## 7.2 异步命令

当前 `gal_data` 路由最长同步等待 60 秒。新 `gas_calibration` 不应复制该阻塞模式。

要求：

- `start/status/finish/cancel` 快速返回；
- `zero/span` 只确认会话已接受动作并进入执行态；
- 最终 `0x6006` 状态通过 `status` 查询；
- LCD 接收任务不能因一次标定命令停止读取串口 60～120 秒。

## 7.3 心跳和会话超时

- `status` 更新 LCD 心跳时间；
- 10 秒无心跳：暂停目标气体高频读取；
- 心跳恢复：恢复当前阶段读取；
- 单气体会话建议最长 30 分钟；
- 超时后停止高频读取和新写命令，但保留四气体维护隔离，等待 LCD 清洗确认和 `finish`；
- 第一版会话保存在 RAM，MCU 重启后清空；启动日志应提示上次校准会话不能恢复，现场需确认已结束供气。

## 8. 正常数据隔离

校准会话开始到 `finish` 之间：

1. 正常采集入口识别四个气体 ID。
2. 跳过四个气体的常规 60 秒 Modbus 读取，避免重复访问和交叉响应数据进入业务链路。
3. 不把校准页面读取的目标气体数值发布为 `RAW_DATA_COLLECTED`。
4. DataManager 不接收四气体维护数据，因此现有十分钟、小时、日算法无需修改。
5. HJ212 构包只处理这一轮存在的正常有效因子，不上传四气体维护值。
6. SD 正常 raw/min/hour/day 不保存四气体维护值；如需要审计，使用专用校准日志，而不是业务历史结构。
7. 颗粒物、风速、风向、气象、噪声和 SHT30 继续正常采集、处理、保存和上传。
8. `finish` 后从下一次正常 60 秒采集恢复四气体。

需要验证当前 DataManager/HJ212 对“本轮缺少四气体”路径无空指针或错误构包；若现有空项语义已覆盖，应复用，不修改小时统计算法。

## 10. 旧接口处理

现有 `gal_data` 还用于颗粒物 DATA/RATIO 校准，不能整体删除。

1. 颗粒物继续走现有 `gal_data`。
2. 新 LCD 的四气体只使用 `gas_calibration`。
3. 四气体通过旧 `gal_data` 请求时返回：

```json
{"operation":"gal_data","code":"NG","reason":"legacy_gas_calibration_disabled"}
```

这样可以防止旧接口绕过会话、目标预设、`0x6006` 结果查询和维护数据隔离。

不得再通过旧接口执行四气体零点，以防旧接口绕过管理员校准会话、目标配置、`0x6006` 结果查询和维护数据隔离。

## 11. 日志建议

新增 INFO/WARNING 诊断标记：

```text
GAS_CAL_SESSION action=start/resume/finish/cancel ...
GAS_CAL_READ id=... value_ppb=... ok=... age_ms=...
GAS_CAL_BUS_DEFER reason=normal_collect ...
GAS_CAL_COMMAND point=zero/span target_ppb=... write_ack=...

GAS_CAL_MAINTENANCE active=0/1 ...
GAS_CAL_RESULT point=... success=0/1 reason=...

```

注意：

- MCU 日志可以记录内部目标值，LCD 接口不返回目标值；
- 每 2 秒成功读取不建议全部使用 INFO，以免日志量过大，可用 DEBUG 或限频；
- 会话状态变化、失败和最终结果使用 INFO/WARNING/ERROR。

## 12. 内存和实时性约束

1. 不新增动态临时任务。
2. 不扩大软件串口 1024 字节缓冲，避免重现 2.0.11 启动重启问题。
3. 校准会话使用单个固定结构体。
4. 最近 20 秒浓度窗口使用固定 10 项 `uint16_t` 环形数组，不使用 `std::vector`。
5. JSON 响应使用固定缓冲或可证明上限的小字符串，单包建议控制在 384 字节以内。
6. 不复制完整配置 JSON。
7. 485 事务有明确响应超时，所有失败路径必须释放互斥锁。

9. 正常 60 秒采集延后应控制在已有调度容忍范围内，不得因校准导致跨分钟长期积压。

## 16. 标准气实测验收

按 O3、NO2、CO、SO2 顺序逐个执行：

1. 通零气并观察浓度稳定。
2. 点击零点，抓取解保护、`0x1000` 和 `0x6006` 全部 Modbus 帧。
3. 确认 `0x6006=0x0001` 后 LCD 显示零点成功。
4. 通入与 MCU 预设一致的标准气，等待浓度稳定。
5. 点击量程点，确认请求中没有 LCD 当前浓度或目标浓度。
6. 抓取写入值：O3/NO2/SO2 为 500，CO 为 5000。
7. 确认 `0x6006=0x0001` 后 LCD 显示量程点成功。
8. 清洗期间继续隔离四气体业务数据。
9. `finish` 后下一轮 60 秒采集恢复四气体。
10. 校准结果断电重启后仍由传感器模组保存。
11. 保存 MCU/LCD 日志、Modbus 抓包、SD 数据和平台时间点用于联合判定。

## 18. 已确认实施决策

1. 量程点启用目标偏差 ±20% 的防误操作限制。MCU 使用最近 20 秒有效样本平均值判断：`abs(avg - target) * 100 <= target * 20`；样本不足 10 个时拒绝执行并返回 `insufficient_samples`，超出范围返回 `concentration_not_ready`。
2. 稳定性提示使用最近 20 秒数据，正常 2 秒采样一次，共 10 个样本。提示结果供 LCD 展示和操作员判断，不代替现场人工确认，也不改变写入模组的配置目标。
3. 旧 `gal_data` 的四气体调用禁用，返回 `legacy_gas_calibration_disabled`；原颗粒物校准逻辑保持不变。
4. 四气体目标保存在 MCU 本地管理员配置中，LCD 校准页面和状态响应均不显示目标值。
5. 新固件版本号设为 `2.0.15`。
6. 新 `gas_calibration` 接口的全部动作要求管理员权限，普通用户请求由 MCU 拒绝。
7. 校准成功后不重启 MCU。清洗完成并收到 `finish` 后退出维护会话，从下一轮 60 秒周期恢复正常采集；校准过程中意外重启则本次会话作废，不能自动续做。
