# TSP ESP32-S3 项目工作日志（2026年8月1日—8月10日）

## 一、日志说明

- 项目名称：TSP 空气微站环境监测终端
- 硬件平台：ESP32-S3，16 MB Flash，PSRAM Disabled
- 固件版本：Firmware 2.0.4
- 主要工作方向：长时间运行稳定性、HJ212 数据上传、SD 卡历史数据与 pending 补传、FFat 配置持久化、采集时间轴和网络校时
- 记录依据：项目 `README.md`、`功能更新.md`、Firmware 2.0.4 变更记录、开发日志、交接文档、Git 提交记录及编译/烧录/串口/SD 卡验证结果

## 二、本阶段总体目标

本阶段围绕设备长期运行时可能出现的实时数据断续、小时数据缺失、堆内存下降、DTU 串口竞争、pending 补传停滞以及 SD 文件异常等问题开展验证和修复。工作原则如下：

1. 先使用串口日志、SD 卡文件和平台 ACK 建立“采集—处理—存储—发送—补传”完整证据链，再决定是否修改代码。
2. 小时统计继续保持每 3 分钟取样、整点结算上一小时的原有规则，本阶段不修改小时统计算法。
3. HJ212 逐包发送间隔继续保持 3000 ms。
4. SHT30 `-101` 问题作为独立硬件/通信问题处理，不混入数据稳定性修改。
5. 大彩 HMI 屏、LED 灯珠灯箱、实时采集、SD 保存和 HJ212 上传需要并行工作，任何修复不得破坏既有接口和报文格式。

### 根因定位与代码修复

1. 修复采集调度：删除 `CollectTask` 在 `vTaskDelayUntil()` 之后对 `xLastWakeTime` 的二次重置，恢复 FreeRTOS 固定周期基准，避免约 60.08 秒的实际周期迟延逐轮累积并跨过墙钟分钟。
2. 修复时间链路：
   - DTU 时间保留秒，统一生成 14 位 `YYYYMMDDhhmmss`；
   - DS1302 RTC 读取保留 `DateTime.second`；
   - `timeInit()`、`updateMillisTime()`、`isValidClockTime()` 同时兼容旧 12 位和新 14 位时间。
3. 优化启动校时：系统启动时立即使用 RTC 初始化时间，不再阻塞等待 DTU 时间命令，优先启动采集任务。
4. 优化运行期网络校时：
   - 使用 `millis()` 计算真实的 24 小时间隔；
   - 首次取得有效 CSQ 后约 5 秒尝试网络校时；
   - 失败或因上传繁忙延后时，5 分钟后重试；
   - 存在实时/pending 上传等待、上传进行中、上传结束不足 1500 ms 或串口锁繁忙时，记录 `TIME_SYNC_DEFER` 并立即让路；
   - 串口锁等待由 3000 ms 缩短为 100 ms；
   - 仅在系统秒处于 10—40 秒安全区间执行校时，避开分钟边界；
   - 网络与系统时间偏差不超过 3 秒时只记录 `TIME_SYNC_VERIFIED`，不重设系统和 RTC；超过 3 秒才记录 `TIME_SYNC_APPLIED` 并更新。
5. 保持小时统计、HJ212 3000 ms 间隔、SHT30、大彩 HMI 屏、LED 灯珠灯箱及 DEBUG 开关不变。
