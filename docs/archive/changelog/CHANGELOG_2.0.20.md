# Firmware 2.0.20 变更记录

## 版本定位

- 2.0.20以2.0.19 HJ212-2017报文修正版为基线，优化断点补传和SD待补文件可靠性。
- 保留2.0.18的通用气体策略和传感器读取优化，不恢复2.0.17认证项目的气体封顶。
- 小时统计逻辑、HJ212逐包3000 ms、SHT30独立、DEBUG开启和Flag默认5均保持不变。

## 本次日志对应的问题

2026-09-02现场日志显示：实时数据在新地址可以收到ACK，但旧待补包
`20260902142422.pkt`连续多个恢复周期没有ACK。旧实现每次只扫描目录前4项，并在首个
实际发送失败后结束本轮，因此同一个失败包可以持续占据后续补传机会。此外，完整
`.pkt`原样保存了生成时的MN；设备MN修改后，旧包仍会带旧MN发送。

## 补传公平性和失败冷却

- 待补扫描按`数据类型 + 时间戳 + 路径`形成稳定顺序，并使用RAM游标循环选择下一批；
  发送失败、等待重建或处于冷却的条目都不会永久挡住后续条目。
- 每5分钟只生成最多4个候选的恢复批次，并且最多进行1次串口发送；为稳定轮转会枚举
  待补目录项，但不会批量读取报文内容，也不会保存无界列表；不改变实时HJ212
  业务的优先级，也不改变逐包3000 ms机制。
- 使用固定8项RAM状态记录最近失败包，不随积压文件数增长。单包连续3次无ACK后进入
  30分钟冷却；冷却期间跳过发送但保留文件。
- 失败次数和游标不写入SD，避免每次重试产生额外闪存/SD写入；MCU重启后该RAM状态
  重新开始统计，但待补文件仍保留。
- 收到ACK后才删除待补文件；无ACK不删除。

## MN等配置变更后的旧数据

- 补传完整包前比较其中的`ST/PW/MN/Flag`与当前HJ212配置。
- 任一字段变化时，不批量扫描或改写SD待补目录，而是在轮到该包时从原始SD记录延迟
  重建：保留原`DataTime`和测量值，使用当前`ST/PW/MN/Flag`、当前协议选择、当前气体
  单位规则以及新的QN重新计算长度和CRC。
- IP和端口是当前DTU传输目标，不写在HJ212报文中，因此无需修改旧包内容。
- 如果原始SD记录暂时或永久不可读，仍保留原完整包并跳过，不使用旧MN发送，也不因
  配置变更而删除或隔离该文件。
- 未发生上述报文头配置变化的完整旧包继续原样补传；这样不会把已经换算的旧气体值
  再次换算。发生MN等变化并重建时，换算来源是SD中的内部基础值，不是旧报文文本。

## 待补文件写入可靠性

- 完整待补包先写入同目录临时文件，依次执行`fwrite`、`fflush`、`fsync`和`fclose`。
- 关闭后重新打开临时文件，逐块比较全部内容并确认没有尾随数据；通过后再重命名为
  最终`.pkt`。
- 日志区分`open/commit/verify/rename/destination_exists`阶段，并记录写入字节数、偏移和
  `errno`，便于判断SD介质、FAT或写回失败位置。
- 任一阶段失败时不删除已经存在的最终包，并继续保留原有`REBUILD_FROM_SD`后备保护。

## 其他修正

- 修复LCD配置查询响应中`"config":" hj212Config"`的多余前导空格，现返回
  `"config":"hj212Config"`。
- 启动时不再无条件创建空`/sdcard/history`目录；只有将来真的出现未知数据类型并走
  `history/other.dat`后备路径时才按需创建。

## 明确未修改

- 不修改小时统计算法。
- 不修改传感器采集、500 ms响应超时、最多3次尝试和300 ms总线间隔优化。
- 不修改SHT30独立采集。
- 不关闭DEBUG。
- 不新增HJ212分包或1024/950长度保护。
- 不修改内部`w34011`、`L90`键及HJ212出口映射。
- 不自动改写设备FFat配置。

## 首次实机验证重点

1. 制造至少3个待补包，让其中第1个服务端不返回ACK；确认恢复游标仍会让第2、3个包
   获得发送机会，且每个恢复周期最多出现1次补传发送。
2. 让同一个包连续3次无ACK，确认出现`RECOVERY_COOLDOWN_SET`，随后30分钟内出现
   `RECOVERY_COOLDOWN_SKIP`而不发送该包。
3. 断网产生旧MN待补包，修改MN并恢复网络；确认日志出现`PENDING_CONFIG_REFRESH`和
   `PENDING_REBUILT reason=config_refresh`，实际报文使用当前MN、原DataTime和原测量值。
4. 检查新产生待补包是否还出现`PENDING_WRITE_VERIFY_FAIL`；如仍出现，用新增的
   `PENDING_WRITE_FAIL stage=...`字段定位失败阶段，并确认后备重建标记仍能保护数据。
5. 查询HJ212配置，确认`config`值没有前导空格；重启后确认SD卡不再无条件生成空
   `history`目录。
