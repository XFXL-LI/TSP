# TSP 继电器自动联动与远程控制需求记录

文档日期：2026-08-25  
适用基线：Firmware 2.0.14  
状态：仅保存需求，未授权实现、编译或烧录  
实施优先级：暂不排序，正式实施前由用户确认

## 1. 现场用途

- GPIO40 所接继电器一般控制无源外部设备。
- 继电器接通时外部设备运行，断开时停止，不联动其他设备。
- 安全状态为继电器断开。
- 主要自动控制场景是颗粒物浓度超标后启动外部设备，浓度恢复后停止。

## 2. 现有接口兼容要求

- 保留现有 `get_config/set_config alarmConfig` JSON 兼容性。
- `alarm_switch` 只表示是否启用自动阈值控制功能，不表示继电器当前物理开关状态。
- 现有 LCD 页面主体不要求重做。
- 因子配置中的 `alarmLimit` 与 GPIO40 的 `alarmConfig` 继续保持不同语义，不得混用。
- 现有字段继续保留：
  - `alarm_sensor`
  - `alarm_upper_limit`
  - `alarm_lower_limit`
  - `alarm_switch`

## 3. 自动模式需求

### 3.1 颗粒物单上限控制

- 自动模式主要按所选颗粒物因子的上限控制继电器。
- 连续 3 次有效实时值大于或等于 `alarm_upper_limit` 后，继电器接通。
- 连续 3 次有效实时值小于 `alarm_upper_limit` 后，继电器断开。
- 本需求不引入额外回差，例如不采用“900 开启、450 关闭”的规则。
- `alarm_lower_limit` 为兼容现有页面和 JSON 保留；颗粒物自动联动中建议固定为 0 或不参与继电器开启判断。
- 颗粒物低于 `alarm_lower_limit` 时不得反向触发继电器接通。

示例目标行为：

```json
{
  "alarm_sensor": "a34001",
  "alarm_upper_limit": 900,
  "alarm_lower_limit": 0,
  "alarm_switch": true
}
```

对应语义：有效实时颗粒物值达到 900 及以上时累计开启次数；低于 900 时累计关闭次数。

### 3.2 数据使用规则

- 只允许 `REAL_DATA` 实时采集事件参与继电器判断。
- 分钟、小时、日数据不得重复累计连续次数。
- 只有 `is_valid=true` 的目标因子值可以参与阈值判断。
- 无效值、未采集到目标因子、因子已关闭或配置不存在时，不得触发继电器接通。
- 传感器连续无效达到保护条件后，继电器必须断开；连续无效的具体次数或时间在实施前确认。
- 自动阈值必须与目标因子的当前配置单位一致；修改气体或颗粒物单位时不得静默沿用不匹配阈值。

## 4. 功能开关与实时生效

- `alarm_switch=false` 时必须立即退出自动模式并将 GPIO40 输出为断开状态。
- `alarm_switch=true` 时启用自动模式，但不能直接将继电器接通；仍需满足有效实时值和连续次数条件。
- 远程或 LCD 成功保存 `alarmConfig` 后，运行中的控制逻辑应立即使用新配置，不应依赖设备重启。
- 配置更新与 GPIO 输出应返回明确结果，不能只返回“配置文件保存成功”。

## 5. 远程手动控制需求

- 手动控制不得复用 `alarm_switch`，避免“自动功能启用”和“继电器直接开关”语义冲突。
- 后续新增独立远程运行命令，支持：
  - `off`：关闭控制并断开继电器；
  - `auto`：按颗粒物自动阈值控制；
  - `manual`：在有效远程控制租约内按远程命令接通或断开。
- 手动接通状态默认不持久化，设备重启后必须回到断开状态。
- 远程手动接通必须带心跳、租约或等效掉线检测；连接失效或租约超时后必须自动断开。
- 不得仅用 CSQ 判断远程控制连接是否有效；具体心跳周期、租约时长和 JSON 操作名在实施前与远程端确认。

建议但尚未冻结的命令形式：

```json
{
  "operation": "io_control",
  "channel": "alarm_relay",
  "mode": "manual",
  "state": true,
  "lease_seconds": 120
}
```

该示例仅用于后续接口讨论，当前固件未实现。

## 6. 安全状态和控制优先级

以下情况继电器必须断开：

- MCU 启动或重启；
- 自动功能关闭；
- 远程手动控制掉线或租约超时；
- 目标因子连续无效达到保护条件；
- 目标因子被关闭、删除或无法读取；
- 控制任务初始化失败。

建议控制优先级：

1. 启动、故障、掉线和无效数据安全保护；
2. 有效租约内的远程手动控制；
3. 自动颗粒物阈值控制。

GPIO40 应只有一个控制模块负责最终写入，自动任务和远程命令不得分别直接操作引脚。

## 7. 状态查询与回包

后续接口至少应能查询或返回：

- 当前控制模式：`off/auto/manual`；
- `alarm_switch` 状态；
- 目标因子 ID、当前值、单位和有效性；
- 上限及连续开启/关闭计数；
- MCU 当前 GPIO 命令状态；
- 最近一次状态变化原因和时间；
- 手动控制租约剩余时间或超时状态。

没有外部触点反馈输入时，只能表述为 `commanded_state` 或“GPIO 命令状态”，不得宣称已经确认继电器物理触点吸合。

## 8. 实施前待确认项

1. 当前 LCD/远程端实际发送的 `alarmConfig` 请求和成功回包样例。
2. 新远程手动控制操作名、字段及旧远程程序兼容要求。
3. 心跳周期、手动租约时长及掉线判定来源。
4. 连续无效多少次或多长时间后执行安全断开。
5. GPIO40 与现场继电器最终确认是高电平接通、低电平断开。
6. LCD 的 `alarm_lower_limit` 当前显示文字是否需要改为兼容说明，或固定为 0。
